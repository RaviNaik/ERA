# Extensive Reimagining of AI (ERA) Course Archive

Welcome to the ERA course repository — a central hub for all versions and sessions of the ERA curriculum.

**🌐 Live site: [https://ravinaik.github.io/ERA/](https://ravinaik.github.io/ERA/)**

| **v5** | **Session 11** — Optimizers by Hand | Adam reproduced number-for-number against `torch.optim` on a 10.77M-parameter nanoGPT (char-level Tiny Shakespeare, RTX A6000) — one weight, five gradients, every intermediate (m, v, m̂, v̂) hand-computed and diffed to **&lt;6×10⁻¹⁷** in float64, then AdamW's decoupled decay separated from plain L2. Bias correction isolated from the schedule: the correction factor c(t) is shown to be non-monotonic and to stay within 1% of 1 only after **76 / 390 / 3,916 steps** at β₂ = 0.95 / 0.99 / 0.999. The update-to-weight ratio ρ = ‖ΔW‖/‖W‖ logged per layer across warmup ∈ {0, 50, 200} — ρ settles at **≈1×10⁻³** for every attention/MLP block, and `argmax(ρ)` lands on the warmup length to within a handful of steps. A two-stage learning-rate sweep (coarse + 2-seed refinement, 57 Aim-tracked runs) across widths 256/512/1024 fits a power law (b ≈ −0.81) and extrapolates to **η\*(4096) ≈ 1.9×10⁻⁴ — confidence explicitly rated LOW**, with the reasons why spelled out rather than hidden behind a clean number. `uv`-managed project, hand-rolled AdamW with a bias-correction toggle `torch.optim` doesn't expose, a `scripts/smoke_test.py` that verifies every code path in seconds without training, and all 57 runs' full metric histories checked into the repo's Aim database. | [Open →](https://ravinaik.github.io/ERA/v5/session11/webapp/) |
| **v5** | **Session 12** — 32 Virtual GPUs & ZeRO | Data parallelism and ZeRO-0/1/2/3 explained, then simulated for real: 32 genuine `torch.distributed` processes (backend `gloo`) on CPU cores — no GPU anywhere — joining a real process group and exchanging real tensors over `all_reduce`, `all_gather`, and a hand-built `reduce_scatter` (Gloo doesn't implement it natively). Every byte reported is **measured**, not assumed: per-rank parameter/gradient/optimizer-state memory drops from **7168 → 224 bytes** across the four stages (exactly 32×), cross-checked bit-for-bit against the closed-form formula, with every stage's final parameters within **4.5×10⁻⁸** of a plain, non-distributed reference step. Communication volume is measured too, with a genuinely counter-intuitive result: ZeRO-1 costs **1.5×** the traffic of plain data parallelism (not less), ZeRO-2 pays that back to exactly **1.0×**, and ZeRO-3 costs **1.5×** again for a different reason. The webapp adds a live memory/communication calculator, a parameter-ownership visualizer, and a worked decision guide (125M model on 1 GPU → 175B model on 512 GPUs); the README carries the full theory, Mermaid diagrams, and results. | [Open →](https://ravinaik.github.io/ERA/v5/session12/webapp/) |
| **v5** | **Session 13** — Reversible LLMs | A 20.1M-parameter GPT (GPT-2 BPE, WikiText-103, RTX A6000) trained on 50M tokens three ways: a standard transformer and two reversible architectures from [*Reversing LLMs for Efficient Training*](https://arxiv.org/html/2512.02056v2): **midpoint** (leapfrog over depth) and **Euler** (symplectic, two streams). Reversible layers rebuild activations during backward instead of storing them, made **bit-exact** with float64 fixed-point residual streams (plain fp32 reversal was measured drifting to gradient cosines of 0.50-0.63). Measured: peak memory **9.45 → 4.61 GB (−51%)**, stored activations **41.8 → 3.0 MB/sequence (14×)** and flat in depth, and Euler reached the **best loss of all runs (4.774 vs baseline 4.828)**, at an **18-26%** throughput cost. The winner was then scaled to 2×/4×/8× batch: the maximum batch grows **2.8× (896 → 2528)**, but at a fixed token budget the loss rose **4.77 → 6.75** for only **+6.6%** throughput, a clean critical-batch-size result. The webapp has interactive loss, memory, speed and max-batch charts; the README carries Mermaid diagrams, pie and xy charts, figures and the full analysis. | [Open →](https://ravinaik.github.io/ERA/v5/session13/webapp/) |
