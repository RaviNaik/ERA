The Training Loop

Five lines run every training job in the world — forward, backward, step, zero-grad. This dashboard takes them apart and checks them by hand: every tensor shape named, one gradient verified against a finite difference, gradient accumulation deliberately broken, the grad norm caught spiking before the loss, MFU measured on a real GPU, and the number 0.1 written out bit by bit. Because every serious training bug is silent. 

logits, loss = model(x, targets=y)   # forward
loss.backward()                      # fill in every gradient
optimizer.step()                     # move every weight
optimizer.zero_grad()                # wipe before the next batch

01 / 09 · THE THESIS

Every serious training bug is silent

A wrong accumulation rule, a misreported gradient, a run sliding toward divergence, a machine running at a tenth of its speed — none of them raise an exception. They all produce a plausible-looking loss curve. The six tasks below are each a way to make one of those bugs visible.

02 / 09 · SETUP

A 10.8M-parameter nanoGPT on char-level Shakespeare

Deliberately ordinary — learned token + position embeddings, pre-norm LayerNorm, causal multi-head attention via scaled_dot_product_attention, a 4× GELU MLP, weight-tied head. The point of the session is the loop, so the model stays close to nanoGPT and the 6N FLOP rule stays easy to reason about.

04 / 09 · TASK 2

Verify one gradient by hand

Pick one scalar weight. backward() reports dL/dw. Measure it the dumb way — nudge the weight up by h, nudge it down by h, watch how the loss moved. In fp64, dropout off.

⚠️ If they disagree
The usual causes: dropout still on (the forward pass isn't repeatable), h too large (the quadratic Taylor term leaks in) or too small (L(w+h) ≈ L(w−h) in fp64), fp32 instead of fp64, or an in-place op corrupting the autograd graph. Ten-decimal agreement rules all of that out.
05 / 09 · TASK 3

Break gradient accumulation on purpose

Correct: sum every per-token loss, divide by the total token count — every token gets one equal vote. Wrong: average each micro-batch's mean loss, so a short micro-batch votes as loudly as a long one. Identical only when micro-batches hold equal token counts.

The static case — class-notes numbers

In a real 120-step run

Two copies of the same initial model, fed the same unequal-length micro-batches (token counts 48, 48, 12) every step, one trained under each rule. The "wrong" rule systematically over-weights the 12-token micro-batch's gradient — a subtly different objective than the one written down.

06 / 09 · TASK 4

Log the grad norm, catch it moving first

The global grad norm sqrt(Σ gᵢ²), logged every step, measured after backward() and before opt.step(). One poisoned batch (targets replaced with noise) is fed mid-run.

The poisoned batch, step by step

📡 Why it matters
One synthetic poisoned batch buys only a one-step lead. On a real run the lead is far longer — a run heading for divergence shows it in the grad norm long before the loss curve bends, which is why the grad norm is the most useful trace on a training dashboard. Clipping (clip_grad_norm_) uses the same number and belongs on from step one.
07 / 09 · TASK 5

08 / 09 · TASK 6

The number 0.1 in fp32, bf16 and fp8 E4M3

0.1 in binary is 0.0001100110011… repeating — never exact. 0.1 = 1.6 × 2⁻⁴, so the unbiased exponent is −4 everywhere; each format rounds the mantissa at a different place. Scale the fraction 0.6 by 2^(mantissa width) and round to nearest.
